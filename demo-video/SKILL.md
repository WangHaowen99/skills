# 产品演示视频

从分镜到成片：配音先行定节奏，Playwright 录连续操作视频，合成时叠字幕、高亮、标注和激光笔，出片前过硬检查。

工具在 [`tools/`](tools/)：`gen-tts.py` 配音、`record-template.js` 录制模板、`compose.py` 合成、`verify.py` 硬检查。
踩过的坑见 [`PITFALLS.md`](PITFALLS.md)——**自检**发现画面不对时再读。

工作目录用 `DEMO_VIDEO_ROOT` 指定（默认 `/tmp/demo-video`），下设 `audio/ vid/ cues/ work/ segments/`。

## 铁律

- **分镜是唯一来源。** 字幕只写在分镜文件里，配音从它生成，cue 从它同步，`verify.py` 比对两者。手抄一遍字幕，迟早出现念的和写的不一样。
- **框当场量。** 高亮坐标在录制那一刻从页面读出来，跟着这一条录像走。事后照着别处的截图填坐标，必然错位。
- **连续视频，不是抽帧。** 有动作的镜头录成连续视频流，按帧率播。抽稀出来的是幻灯片，动作看不出是怎么发生的。
- **说完再切。** 画面短于配音就是截断。宁可画面多停一会儿，不能话说一半切走。

## 步骤 1 · 摸清场景，出镜头清单

**先不写文案。** 改一句字幕的代价一路上涨：

| 阶段 | 改一句的代价 |
|---|---|
| 镜头清单 | 改一行字 |
| 字幕文案 | 重生成这一镜配音 |
| 配音之后 | 还要重核镜头容量，装不下就得重录 |
| 成片之后 | 加上重建、重检、重出片 |

所以分两关对齐，每关拿到用户确认再往下。

**先问清四项**，已知的不重复问：

- **给谁看**——客户宣讲／内部评审／新人上手，决定详略和措辞
- **要让人记住哪一句**——整片的落点
- **篇幅上限**
- **录什么环境**——哪个系统、账号能不能登、要展示的数据是不是已经就绪

**再出镜头清单**，每镜一行，只写「画面上有什么」，不写字幕：

```
3-0  中栏打开配置文件，滚到「生效范围」    约 10s
3-1  同一段的来源标注                      约 8s
3-2  右栏的确认卡，专家补一句要求          约 12s
```

清单要当场核对**画面真拍得出来**：那个界面此刻是不是这个状态、数据在不在、要讲的东西屏幕上有没有。跳过这一步的典型下场是——文案写好、配音也录了，才发现某一镜的面板是空的，只能连文案带镜头一起重来。

**完成标准**：用户确认了镜头的取舍、顺序和大致时长。

## 步骤 2 · 写字幕

**先写 2~3 镜给用户定调**，语气、人称、详略对齐之后再铺全篇——通篇写完再改人称，等于全部重写。

每镜一段，`###` 开头，标号形如 `幕-序`（`3-0`、`5-in`）：

```markdown
### 3-0 规则写在哪里
- **操作**：中栏打开配置文件，滚到「生效范围」那一节
- **高亮**：生效 / 不生效 两组条目
- **字幕**：这份配置不只是一段说明文字。它划定的范围，后面每一步都严格照着来。
- **亮点**：范围先于内容
```

`gen-tts.py` 只认这个结构（`操作`/`高亮` 行之后紧跟 `字幕` 行）。

文案按讲解语气写，说机制不说好处，不堆形容词。

**完成标准**：每一镜都有字幕，字幕说的就是那一镜画面上真会出现的东西，且用户确认过语气。

## 步骤 3 · 配音

```bash
DEMO_VIDEO_ROOT=... python3 tools/gen-tts.py          # 全量，文本没变的自动跳过
DEMO_VIDEO_ROOT=... python3 tools/gen-tts.py 3-0 5-1  # 只重生成指定几镜
```

声音用 `VOICE`（默认 `zh-CN-XiaoxiaoNeural`）、语速用 `SPEED`（默认 1.3）、需要代理设 `DEMO_VIDEO_PROXY`。

把每镜时长记下来：**这就是每个镜头要拍多久**（配音 + 0.3 秒）。

**完成标准**：每镜都有 `audio/<id>.m4a`，且拿到了它的秒数。

## 步骤 4 · 录制

复制 `tools/record-template.js` 到 `~/.playwright-mcp/<名字>.js`，填「登录与打开」和「镜头」两段，用 `browser_run_code_unsafe({ filename })` 跑。

一次 run 录一段连续录像，里面顺序拍若干镜头。每镜的写法固定：

```js
start('3-0');
await scrollToText('^生效范围$', 140, 1.8);      // 逐帧写 scrollTop，快速滚到位
await p.waitForTimeout(400);                     // 等它停稳
R['3-0'] = await boxOfText('^(生效|不生效)：');   // 停稳之后再量框
await holdTo('3-0');                       // 补足到配音时长
```

返回的 `marks` 是每镜在这段录像里的毫秒区间，`rects` 是当场量到的包围盒——原样填进 cue。

**完成标准**：每镜的 `marks` 区间 ≥ 配音 + 0.3，且 `rects` 不为 null。

## 步骤 5 · 写 cue 并合成

一幕一个 `cues/<幕>.json`，数组，每项一镜：

```json
{
  "id": "3-0",
  "chip": "第 2 步 · 配置规则",
  "video": "vid/r20/page@xxx.webm",
  "from": 36266, "to": 46927,
  "rects": [{ "rect": [0.184, 0.379, 0.538, 0.462], "win": [0.26, 1.0] }],
  "notes": [{ "at": [0.06, 0.16], "attach": 0, "win": [0.26, 1.0],
              "text": "范围逐条写明哪些生效、哪些不生效" }],
  "pointer_path": [[0.26, 0.44], [0.58, 0.60], [0.30, 0.76]],
  "subtitle": "…（与分镜逐字一致）"
}
```

- `win: [起, 止]` 是镜头时长的比例，框和标注只在这段时间出现——滚动镜头必须给，否则框会漂。
- `pointer_path` 是激光笔的落点序列，合成时大部分时间停在点上、要挪的时候快速平移过去。关键点给 3~5 个就够。
- `attach` 指向第几个框，用来画引线。

```bash
rm -rf "$DEMO_VIDEO_ROOT/work/a3"        # cue 改了必须清，否则用的是上一版的帧
DEMO_VIDEO_ROOT=... python3 -c "
import sys; sys.path.insert(0, 'tools')
import compose
compose.build('a3', 'frames/a3', 'cues/a3.json', 'segments/a3.mp4')"
```

**完成标准**：每一幕都产出 `segments/<幕>.mp4`，构建过程无报错。

## 步骤 6 · 硬检查

```bash
DEMO_VIDEO_ROOT=... python3 tools/verify.py a1 a2 a3 …
```

拦四件事：字幕缺失或与分镜不一致、配音缺失、镜头不是连续视频、画面装不下配音。

**完成标准**：输出「检查通过：N 镜」，N 等于分镜里的镜头数。

## 步骤 7 · 逐帧自检

`verify.py` 查不出画面本身好不好。成片后按 1.2 秒一段抽样，每段抽帧比对：

- **抖动**：数「相邻帧差大、但隔一帧差很小」的帧。**必须为 0**，这是两态抖动的指纹。
- **滚动是否连续**：看最长连续动作段的帧数。只看平均帧差没用——快速平滑的滚动帧差也很大，靠的是动作是否成段。
- **高亮是否落在字幕带里**：所有 rect 的 `y + h > 0.855` 且横向落在 0.16~0.85 的，逐个渲染出来看。

再挑几帧实际看一眼：框有没有框中要讲的东西、字幕和画面是不是一回事。

**完成标准**：抖动 0 段；每个带高亮的镜头都渲染过一帧确认框对了。

## 步骤 8 · 出片

```bash
python3 -c "
import sys; sys.path.insert(0, 'tools')
import compose
compose.concat(['…/segments/a1.mp4', …], '…/full_raw.mp4')"
ffmpeg -i full_raw.mp4 -vf "scale=1920:1080:flags=lanczos" \
  -c:v libx264 -preset slow -crf 20 -pix_fmt yuv420p -c:a aac -b:a 160k \
  -movflags +faststart 成片.mp4
```

**完成标准**：成片时长 ≈ 各镜配音之和，分辨率与目标一致。

## 换一个产品要动哪几处

流程和工具是通用的，这几处是跟界面绑的，第一次用先过一遍：

- **加载判据**：模板里 `DEMO_LOADING_TEXT` 填你这边的加载提示文案，等它消失再开拍。没有就留空，只靠定时等待。
- **主色**：`DEMO_VIDEO_ACCENT`（`#2a78d6` 或 `42,120,214`）换成和界面同色系，高亮和标注才不突兀。
- **字体**：默认按 macOS → Noto → 文泉驿的顺序找，找不到会直接报错（不会悄悄落到方块字）。要指定用 `DEMO_VIDEO_FONT` / `DEMO_VIDEO_FONT_SUB`。
- **WebGL 图谱**：`graphNode()` 认的是某一类渲染运行时的形状，不是通用协议。换图库只需改「怎么拿到运行时」和「节点坐标叫什么」，外面的点击和缩放不用动；摸不到返回 null。
- **去抖阈值**：`SHIMMER_RATIO` / `SHIMMER_FLOOR` 是在一套界面上试出来的。换界面第一次用要验一下——压太狠会把真实的慢速变化也冻住，看步骤 7 的抖动统计。

## 改文案

改动分镜里的字幕之后，按镜逐个过：重生成配音 → 比对新时长与镜头容量 → 同步 cue 里的 subtitle → 清 `work/` 重建 → 重跑步骤 6、7。

配音变短：裁 cue 的 `to`，保持原速，不要留给合成器加速。
配音变长超过原镜头容量：只能重录那一镜。
