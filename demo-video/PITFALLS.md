# 坑

自检发现问题时对照这里。每条都是实拍踩出来的，不是推测。

## 画面

**整栏文字持续发抖。** 页面上有流式输出（助手在跑、日志在刷）时，每个 tick 都让整块面板重新栅格化，文字反锯齿跟着翻，录像里是严格的 A/B/A/B：相邻帧差 ~2.0，隔一帧差 ~0.03。`compose.py` 的 `deshimmer` 专治这个——维持一张「当前在放的参考帧」，新帧和参考帧差得明显、却和近期某个旧状态几乎一样，就判定翻回去了，按住参考帧。能避开就避开：**尽量在助手空闲时录**。

**判两态抖动不能只比上上帧。** 25fps 抽成 30fps 会插重复帧，A/B/A 的节奏被打乱，只比上上帧漏一半以上。必须回看一个状态窗口（`STATE_WINDOW`）。

**滚动录成了几次瞬移。** `p.mouse.wheel` 每次是一趟 CDP 往返，Chromium 又把滚动合并成动画，录到的是 96% 静止 + 十来次跳。改成逐帧写 `element.scrollTop`（40ms 一步、smoothstep 缓动）。**例外**：WebGL 画布的缩放用 wheel 正常，因为 canvas 自己处理滚轮事件；负值推近、正值拉远。

**录像里没有鼠标指针。** Playwright 的 `recordVideo` 不画光标，所以纯 `mouse.move` 的漂移在成片里完全看不见。要让画面「有动静」，靠的是激光笔（合成时叠的）和真实的页面变化，不是鼠标轨迹。

## 高亮与标注

**框在底部等于没画。** 字幕带占画面底部约 0.855 以下、横向 0.16~0.85。落在这个区域的框会被完全盖住——量出来是对的，成片里看不见。目标控件本来就在底部时（发送按钮、底部操作条），要么把框收到字幕带右侧（x > 0.86），要么改框别的东西，用标注说明。

**滚动镜头的框会漂。** 框是固定坐标，画面往上走，讲到的那句早滚出框外了。给 rect 和 note 配 `win: [起, 止]`（镜头时长的比例），让框只在滚停之后出现。

**框必须当场量。** 同一个页面在不同项目、不同阶段，标签文字长度不同，导航栏每一格的 x 会差几个百分点。事后按另一处的截图填坐标，一定错位。

**自动量出来的框常常太大。** 匹配到外层容器就把整栏圈进去了，等于没高亮。量完要回看一眼渲染帧，收紧到真正要讲的那几行。

## 交互

**自定义控件过不了可点性检查。** 视觉化的复选框、开关，`elementHandle.click()` 会等到超时（一次 30 秒，还会把镜头时长撑爆）。鼠标只负责移过去，触发在页面内做；React 受控组件改 `.checked` 无效，要点它的 `label`。

**页面上不止一个 textarea / canvas。** 决定卡里有「退回说明」输入框，右下角有小地图 canvas。按占位符认输入框，按面积认画布，别拿 `querySelector` 的第一个。

**视图切换按钮点了不一定生效。** 有选中态时点「图」可能被挡回去。切完要回读一帧确认，不能假定成功。

## 时长与文案

**配音时长决定一切。** 先生成配音，再按它定每镜的秒数（配音 + 0.3）。画面短于配音就是截断，`verify.py` 会拦；画面远长于配音，合成器会加速到 1.8 倍硬塞，动作看着发飘——**宁可裁窗口，别靠加速**。

**改一句文案要连带查三处**：重生成配音 → 新时长是否还装得下 → cue 里的字幕要同步（`verify.py` 比对 cue 与分镜，不一致就拦）。文案变长超过原镜头容量时，只能重录。

## 构建

**`work/` 会留脏。** cue 改了但 `work/<幕>/` 没清，成片用的还是上一版的帧，而且 `verify.py` 也查不出来——它数的就是那些脏帧。改完 cue 先 `rm -rf work/<幕>`。

**`attach` 下标会错位。** 标注的引线按下标找框，框被 `win` 过滤后下标变了。`compose.py` 已做重映射，框这会儿不显示就不画引线。
